# Предохранители CDOS — день 1

Детерминированные проверки, которые срабатывают независимо от того, прочитала
модель правило или нет. Это ответ на измеренный факт: правило про пересборку
манифеста записано в `CLAUDE.md` §3.2 крупно, с историей двух кирпичей, и всё
равно нарушено в 4 коммитах из 32, тронувших покрытые файлы (12.5%).

Всё здесь — Python + stdlib. Ни одной зависимости. Каталог `.claude/` в
`.gitignore` и **вне манифеста целостности** (проверено: 123 файла, только
`apps/`, `scripts/`, `packages/`, `tools/`, `bootstrap.ps1`,
`requirements-runtime.txt`). Приложение эти файлы не видит вообще.

## Что стоит

| Файл | Событие | Что делает |
|---|---|---|
| `commit_guard.py` | PreToolUse на `^Bash$` | Не даёт закоммитить правку покрытого файла без пересборки `integrity.json` |
| `charcheck.py` | PreToolUse на `^Edit$\|^Write$\|^MultiEdit$` | Не пускает в файл иероглифы, невидимые и управляющие символы, латиницу внутри русского слова; требует BOM у `.ps1` с кириллицей |
| `_coverage.py` | — | Читает покрытие манифеста из `integrity.py` через `ast`. Не копия: покрытие уже менялось, вторая копия разошлась бы молча |
| `selftest.py` | — | Проверка обоих хуков на способность краснеть |
| `preflight.py` | — | Гоняет ВСЕ шаги сборки на чистом `git worktree` — до пуша, а не после |

## Почему именно эти точки

**`git commit`, а не конец хода.** Промах случается в момент коммита; пока файл
лежит изменённым в рабочем дереве, всё в порядке. Проверка на `Stop` пилила бы
на каждом ходу посреди незаконченной работы, а предохранитель, срабатывающий не
по делу, выключают в тот же день.

**`PreToolUse`, а не `PostToolUse`.** `PostToolUse` срабатывает после успешной
записи и отменить её не может — испорченный файл уже был бы на диске.

**Якоря в matcher обязательны.** Matcher — это regex без якорей, поэтому
`Edit.*` поймал бы ещё и `NotebookEdit`.

## Проверка

```bash
./venv/bin/python .claude/hooks/selftest.py
```

17 проверок: 6 «обязан поймать» и 11 «не смеет трогать». Второй список важнее
первого — ложное срабатывание дороже пропуска.

## Чего это НЕ даёт

- **Не ловит коммит рукой из терминала.** Хуки видят только команды, запущенные
  Claude Code. Полное покрытие — git pre-commit hook, но это отдельное решение,
  затрагивающее второго разработчика.
- **Не заменяет CI.** Источник истины — `.github/workflows/ci.yml`. Хук лишь
  ускоряет обратную связь.
- **Отваливается молча.** Если Anthropic переименует событие, хук перестанет
  вызываться без единого сообщения. Дешёвая самопроверка — запустить
  `selftest.py`.
- **Не работает у коллеги автоматически.** `settings.local.json` игнорируется
  git; у него другой путь к Python.

## preflight.py — почему появился

За одну сессию сборка краснела трижды, и все три раза причина была одна:
локально проверялось не то, что проверяет CI.

1. Манифест собрался с незакоммиченными правками соседней сессии — на CI хеш
   файла не сошёлся.
2. Тест писал учётные записи в настоящую `data/app.db` и падал со второго
   прогона; на CI база чистая, поэтому первый прогон был зелёным.
3. Тест импортировал модуль, лежавший в рабочем дереве, но ещё не уехавший в
   репозиторий.

Общее — рабочая копия отличается от того, что видит сборка: в ней чужие правки,
своя база и незакоммиченные файлы.

```bash
./venv/bin/python .claude/hooks/preflight.py            # проверить HEAD
./venv/bin/python .claude/hooks/preflight.py --rev abc  # разобрать чужое падение
```

Проверено на способность краснеть — на настоящих упавших коммитах: `0b0f16a`
даёт провал ровно на манифесте, `917baee` — ровно на pytest. Совпадает с тем,
что говорила сборка.
