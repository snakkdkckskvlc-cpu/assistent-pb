# Работа с моделью

Переехало из CLAUDE.md §6 дословно: нужно только здесь, а в постоянном контексте
занимало ~515 токенов каждую сессию.

Ollama на CPU. Генерация упирается в память, а не в процессор.

- **`num_ctx` менять нельзя без причины** — смена перезагружает модель.
  Значение подбирается по объёму RAM (`config.py::_auto_num_ctx_legal`).
- **Длинный запрос молча обрезается** — Ollama срезает начало вместе с
  системным промптом. Так уже был получен ноль находок на договоре. Резать
  документ на части самим, а не надеяться на окно.
- **Структурированный ответ — через `format: json` и разбор в Pydantic.**
  Модель ошибается в JSON; разбор обязан переживать это без падения задачи.
- **Обвязка важнее модели.** Замерено: голая модель находит 10 красных рисков
  из 23, с промптом, RAG и проверкой цитат — 16. Выбрасывать обвязку ради
  «более умной модели» нельзя.
- **Проверять то, что модель утверждает.** Цитата сверяется с текстом
  документа, номер статьи — с выданным контекстом. Непроверенное помечается
  в интерфейсе.
- **Любое утверждение о качестве — с замером.** В этом проекте принято сравнивать
  на датасете и писать цифры в коммит. «Стало лучше» без числа не принимается.

Промпты — в `resources/prompts/`, не в коде.

## Предел требований на один вызов

Локальная 7B держит 3–5 требований за раз, дальше начинает терять. Многотребовательный
промпт разбивается в цепочку одношаговых, а не наращивается. Это измеренное свойство
слабых моделей, не особенность конкретного промпта.

## Замер до и после — обязателен

```bash
./venv/bin/python scripts/evaluate_spellcheck.py     # орфография
./venv/bin/python scripts/evaluate_ask.py            # вопрос по документу
./venv/bin/python scripts/evaluate_prompts.py        # промпты
```

Обе цифры — в тело коммита. Хуже, значит откат и запись отрицательного
результата: так уже было в `752efb1` (87% против 90%, откачено) и `b32d220`
(Saiga-Mistral проиграла вдвое). Отрицательный результат — такой же результат.
