# Changelog

Все значимые изменения проекта фиксируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [0.7.0] — 2026-07-20 · Стиль писем из архива, история задач, пакетная проверка, .eml

Оставшиеся этапы внешнего плана развития (кроме roles и публичного
GitHub Pages-лендинга — они противоречат однопользовательскому офлайн-режиму
и коммерческой тайне проекта) + чистка накопившегося lint-долга.

### Добавлено
- **Реальные письма компании как образцы стиля генерации**: отдельная
  ChromaDB-коллекция `letters_history` (одно письмо = один документ),
  наполняется разовым скриптом `scripts/index_letters.py` из ZIP/папки
  с архивом писем (сам архив в git не попадает — коммерческие данные).
  Генерация подтягивает 2 ближайших к наброску письма как образцы. По итогам
  живого прогона в промпт добавлено жёсткое правило «факты — только из
  наброска, иначе плейсхолдер [номер]/[Имя Отчество]»: без него модель
  переносила из примеров правдоподобные номера договоров.
- **История задач**: таблица `task_history` (SQLite), запись из воркера
  очереди через колбэк `on_task_finished`, `GET/DELETE /api/history`,
  страница «🕘 История задач». Хранится сводка и тайминги, тексты
  документов — нет.
- **Пакетная проверка договоров** (`POST /api/batch`, страница, карточка на
  главной): до 20 файлов одной задачей, тип каждого определяется офлайн-
  классификатором (`services/classify.py`: договор/письмо/акт/смета/прочее
  по взвешенным лексическим маркерам), юр. анализ запускается только для
  договоров. Сводный DOCX-отчёт по пакету.
- **.eml-экспорт письма**: кнопка «📧 Скачать .eml» — готовый черновик для
  Outlook/Thunderbird (адресат, тема, сопроводительный текст, DOCX на
  бланке во вложении, `X-Unsent: 1`).

### Исправлено
- `ruff check .` снова зелёный по всему репо (CI на main был красным из-за
  ~14 старых находок в файлах, не тронутых фичами): конфиг TC-правил под
  FastAPI/pydantic (импорты моделей в роутерах обязаны оставаться
  рантайм-импортами), annotation-only импорты под TYPE_CHECKING, формат
  12 давно не форматированных файлов.
- `/api/download` отдаёт корректный media-type по расширению файла
  (раньше и .eml уходил как DOCX).

## [0.6.0] — 2026-07-17 · Фиксы код-ревью, живой счётчик токенов, фидбек, бенчмарк

Сверка внешнего 12-этапного плана развития с фактическим состоянием репо
(этапы 0–2 — референсы/адресаты/LanguageTool — уже были сделаны). В работу
взяты: все 14 оставшихся находок `/code-review` от 2026-07-16, этапы
«стриминг», «фидбек», «бенчмарк» внешнего плана — в право-размерном для
нашего масштаба виде. RAG на истории писем, история задач, батч-обработка,
классификация и .eml-экспорт из внешнего плана осознанно не взяты.

### Исправлено (14 находок код-ревью)
- **Критично**: свежая установка на Windows падала на шаге 5/8 — `bootstrap.ps1`
  ставил зависимости из несуществующего `requirements.txt`. Заменено на
  editable-установку трёх пакетов (`pip install -e apps/backend -e
  apps/desktop -e packages/rag`) — единый источник правды с
  `install/README.md` и `pyproject.toml` каждого пакета.
- Баг overlap в sentence-aware чанкере (`packages/rag/.../chunking.py`):
  carry-цикл безусловно переносил последнее предложение куска независимо от
  бюджета `overlap_words` — force-split фрагмент крупнее бюджета дублировался
  в следующий чанк целиком, раздувая его выше `max_words`. Теперь перенос
  строго ограничен бюджетом.
- Дедуп повторных находок LanguageTool+LLM в проверке орфографии (одна и та
  же ошибка раньше показывалась дважды с разными `type`).
- Фильтр false positives LanguageTool на именах собственных/организациях
  (заглавное слово не в начале предложения — не флажится).
- Единый источник фирменного глоссария — `tools/languagetool/dict/
  spelling_global.txt` теперь читается и в LLM-промпт, а не дублируется там
  прозой.
- `languagetool.py`: общий lifespan-scoped `httpx.AsyncClient` вместо нового
  соединения на каждый вызов (как в `llm.py`); убран фолбэк `or ctx_text`,
  подставлявший весь контекст-сниппет в пустой срез поля `before`.
- `pipelines/spellcheck.py`: NLTK-чанкинг вынесен в `asyncio.to_thread` —
  раньше блокировал общий event loop.
- `pipelines/legal.py`: offset поля `_цитата_offset` теперь в ОРИГИНАЛЬНОМ
  тексте договора (гибкий по пробелам regex), а не в схлопнутой копии;
  коллизия коротких ID чанков (dict comprehension молча теряла чанк) —
  цикл с пере-сидом до уникальности.
- `/api/health`: три пробы (Ollama/RAG/LanguageTool) идут через
  `asyncio.gather` вместо последовательного ожидания.
- LanguageTool setup/start скрипты (bash + PowerShell): версия папки
  определяется глобом `LanguageTool-*`, а не хардкодом «6.6».
- Флаки-юнит-тест и хрупкий smoke-тест grounding (регэксп по отрендеренному
  промпту) переведены на monkeypatch вместо реальной сети/хрупкого парсинга.

### Добавлено
- **Живой счётчик токенов** во время генерации вместо статичного «Обработка…»
  — `llm.py::chat` умеет стримить (`on_delta`), `Task.tokens` растёт по мере
  ответа модели, `app.js` дописывает «(…N токенов)» к прогресс-лейблу.
  Полноценный SSE-рендеринг сознательно не делаем: все три функции
  возвращают структурный JSON, частичный JSON нерендерибелен — используем
  уже существующий канал polling `/api/tasks/{id}`.
- **Фидбек 👍/👎** под результатом любой из трёх функций — новая таблица
  `feedback` в SQLite, `POST /api/feedback`, один общий JS-хелпер
  (без правок трёх HTML-страниц).
- **`scripts/benchmark_models.py`** — самостоятельный скрипт (только httpx):
  прогоняет каждую установленную в Ollama модель на 3 реалистичных задачах,
  меряет задержку первого токена и ток/с, пишет таблицу + JSON. Для решения
  «переключаться ли на Saiga-Mistral-7B» — по цифрам с боевого сервера, а не
  вслепую. `scripts/modelfiles/saiga_mistral_7b.Modelfile` + README — как
  собрать Saiga в Ollama, если нужно включить её в сравнение (модель по
  умолчанию не меняется).

## [0.5.1] — 2026-07-17 · LanguageTool на Windows

LanguageTool-интеграция из 0.5.0 была собрана и проверена только на
macOS (bash-скрипты) — на реальном Windows-сервере компании не имела
пути включения вообще. Добавлен полный Windows-путь.

### Добавлено
- `tools/languagetool/setup.ps1` — Windows-аналог `setup.sh`: скачивает
  портативный JDK 17 (Temurin, windows x64) и релиз LanguageTool в тот
  же каталог, ничего не ставит в систему.
- `tools/languagetool/start.ps1` — Windows-аналог `start.sh`: поднимает
  сервер на 127.0.0.1:8081 с тем же словарём `dict/spelling_global.txt`.
- `bootstrap.ps1`: новый необязательный шаг «7/8 · LanguageTool» —
  вызывает `setup.ps1`; при неудаче (нет сети и т.п.) установка **не
  прерывается**, просто предупреждение — LanguageTool и раньше был
  спроектирован как graceful-degradation фича (`languagetool_ready` в
  `/api/health`). Сгенерированный `start.bat` теперь заодно тихо
  поднимает LanguageTool перед запуском приложения, если шаг прошёл
  успешно.
- Обновлены `docs/07-ops/install-windows.md` и `install/README.md`
  (шаги теперь 1/8…8/8 вместо 1/7…7/7).

## [0.5.0] — 2026-07-16 · Референс-ревью: чанкинг, grounding, LanguageTool

Изучены 5 референс-проектов (`docs/08-references.md`), реализованы
конкретные, право-размерные для нашего масштаба находки — не копии кода
(разный стек у большинства), а адаптированные паттерны/алгоритмы или
реально переиспользуемые внешние модули там, где это было возможно.

### Добавлено
- **Sentence-aware чанкинг** (`packages/rag/src/fire_safety_rag/chunking.py`)
  — по мотивам чанкера private-gpt: сначала делим на предложения (NLTK Punkt,
  модель для русского, vendored offline в `resources/nltk_data/`, сеть не
  нужна), затем упаковываем в чанки по словам; предложение длиннее лимита
  режется принудительно. Заменяет наивную нарезку по словам и в RAG-индексаторе,
  и в проверке орфографии — устраняет дублирование кода между пакетами.
- **Grounded-цитирование в юр. анализе** (`pipelines/legal.py`) — по мотивам
  private-gpt (`generate_shorter_id`, адаптировано без их DI/streaming-обвязки):
  каждый RAG-чанк получает короткий ID, модель указывает его в новом поле
  `источник_фрагмента`, ответ проверяется на реально отданные в контекст
  чанки — есть флаг `_источник_подтверждён`.
- **Quote-anchoring находок** — по мотивам OpenContracts (`is_grounding_source`):
  `цитата_из_договора` теперь проверяется как реальная подстрока присланного
  текста договора (`_цитата_найдена`), а не принимается на слово. Оба флага
  отображаются в UI (`legal.html`) бейджами.
- **LanguageTool как офлайн первый проход перед LLM в проверке орфографии**
  (`infrastructure/languagetool.py`, `pipelines/spellcheck.py`) — реальный
  сервер LanguageTool (не embedding, LGPL — только HTTP-вызов отдельного
  процесса, копилефт не затрагивается) на вендоренном портативном JDK
  (`tools/languagetool/`, не в системе). Отраслевой словарь
  (`tools/languagetool/dict/spelling_global.txt`) исключает false positives
  на терминах АПС/СОУЭ/ГОСТ/СП и т.п. Результаты LT и LLM объединяются в
  общий список ошибок с пометкой источника.
- `/api/health` сообщает `languagetool_ready`.
- Юнит-тесты: `test_chunker.py` (переписан под sentence-aware поведение),
  `test_legal_grounding.py`, `test_languagetool.py`; smoke-тест grounding
  через реальный HTTP-вызов `/api/legal`.

### Изменено
- `pipelines/legacy.py` (190 строк, три разные функции в одном файле)
  разделён на `pipelines/{spellcheck,legal,letter}.py` + общий
  `pipelines/_prompts.py`.

## [0.4.0] — 2026-07-16 · Sprint 4. Справочник адресатов + фикс-пасс

### Добавлено
- **Справочник адресатов** (SQLite, `data/app.db`): список/создание/удаление
  через `/api/addressees`, дефолтные адресаты + возможность добавлять свои
  прямо из UI (комбобокс на странице письма, даталист + сохранение).
  Тон подсказки (`tone_hint`) подтягивается в промпт письма по типу адресата.
- `apps/backend/tests/smoke/test_addressees.py` — CRUD-покрытие новой функции.

### Исправлено
- **Краш приложения при старте**: `DELETE /api/addressees/{id}` (204 + `-> None`)
  падал на этапе импорта роутера (FastAPI/Starlette assert). Добавлен
  `response_model=None`.
- **Фирменный бланк письма**: реальный `letterhead.docx` не содержал 5 из 8
  плейсхолдеров, которые уже вычислял код (`{{date}}`, `{{subject}}`,
  `{{signoff}}`, `{{sender_position}}`, `{{sender_name}}`) — тема письма, дата
  и подпись отправителя молча терялись при генерации DOCX. Плейсхолдеры
  добавлены в шаблон.
- Подстановка плейсхолдеров в DOCX переведена на однопроходный regex —
  устранён риск повторной подстановки, если значение одного поля случайно
  содержало текст вида `{{другое_поле}}`.
- Блокирующие вызовы (SQLite, генерация DOCX, OCR/парсинг загруженных
  файлов) убраны с общего event loop через `asyncio.to_thread` — раньше они
  подвешивали весь бэкенд (единственный воркер очереди) на время своей работы.
- `/api/health` пересоздавал ретривер (и заново грузил embedding-модель
  ~1.3 ГБ) на каждый вызов — переведён на закешированный singleton.
- Юридический анализ договора: 5 последовательных запросов к ChromaDB
  объединены в один батч-запрос (`retrieve_many`).
- Path traversal в загрузке файлов (`services/uploads.py`) — имя файла
  теперь санитизируется так же, как в `downloads.py`.
- Валидация справочника адресатов: пустое/из пробелов имя больше не
  проходит; уникальность и поиск по имени теперь регистронезависимы
  (`COLLATE NOCASE`) и согласованы с сортировкой в списке.
- Единый `httpx.AsyncClient` на всё приложение вместо нового соединения на
  каждый вызов Ollama; отдельный короткий connect-таймаут (5с), чтобы
  недоступная Ollama не блокировала запрос на все 15 минут read-таймаута.
- Изоляция тестов от реальных `data/app.db` и `data/outputs/`.

  с RAG-подсказками по ФЗ/ГК РФ, генерация официальных писем на бланке.
