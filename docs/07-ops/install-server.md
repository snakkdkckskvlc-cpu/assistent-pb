# Установка на сервер

Приложение переезжает с рабочих мест на один сервер: сотрудники открывают его
браузером с любого компьютера, вычисления (модель, распознавание, поиск по
нормативке) идут на сервере.

Сервер: Windows, Ryzen 5 5600, 128 ГБ RAM, без видеокарты.

> В брифе `server-deployment.md` упоминается `systemd` — это Linux. Сервер
> под Windows, поэтому автозапуск делается планировщиком задач; всё остальное
> из брифа применимо как есть.

---

## Порядок установки

### 1. Обычная установка

```powershell
.\bootstrap.ps1
```

Ставит Python, Ollama с моделью, Tesseract, Poppler, LanguageTool, зависимости
и индексирует нормативку. Ярлык на рабочем столе для сервера не нужен — он
запускает оконный режим.

### 2. Завести учётные записи

Пароля в приложении нет: сотрудник вводит логин **один раз**, дальше
компьютер подставляет его сам, и остаётся нажать «Вход».

Но придумать логин на ходу нельзя — учётную запись заводит администратор.
Иначе опечатка создавала бы нового «сотрудника», и человек терял бы доступ к
своим документам.

```powershell
python scripts\add_user.py ivanov --admin
python scripts\add_user.py petrova
python scripts\add_user.py --list
python scripts\add_user.py petrova --disable   # закрыть доступ уволившемуся
```

**Отключение — единственный способ отозвать доступ**, раз пароля нет. Оно же
сразу закрывает открытые сессии.

### 3. Проверить запуск руками

```powershell
python scripts\run_server.py
```

Открыть с другого компьютера `http://<адрес-сервера>:8000` — должна появиться
форма входа.

### 4. Автозапуск

```powershell
.\tools\service\install_task.ps1
```

Регистрирует задачу планировщика, стартующую при загрузке — **до входа
кого-либо в систему**. Ollama ставит свою службу сама, LanguageTool поднимает
сам backend.

## ⚠️ Под какой учётной записью работает приложение

Это решение по безопасности, а не деталь: **шифрование документов привязано к
учётной записи**, под которой идёт приложение.

| Вариант | Плюс | Минус |
|---|---|---|
| `SYSTEM` (по умолчанию) | ничего не настраивать, нет пароля | ключи DPAPI доступны любому процессу с правами SYSTEM или администратора — от администратора этой машины шифрование не защищает |
| Выделенная учётная запись (**рекомендуется**) | ключи принадлежат только ей | завести пользователя, дать «Вход в качестве пакетного задания», хранить пароль |

```powershell
.\tools\service\install_task.ps1 -UserId "SERVER\assistentpb"
```

**Менять учётную запись после запуска нельзя.** Файлы, зашифрованные под одной,
под другой не читаются — см. [security.md](../05-quality/security.md).

## Что защищает сервер

До переезда backend слушал только `127.0.0.1`, и разграничения доступа не было
вовсе — это было безопасно ровно потому, что снаружи до него было не достать.
Теперь до приложения дотягивается вся внутренняя сеть, и защиты ровно две:

1. **Вход по логину.** Все роутеры закрыты; открыты только форма входа и
   `/api/health` (и тот отдаёт неавторизованному лишь «сервер жив», без блока
   безопасности).
2. **Разграничение «только своё».** Сотрудник видит свои документы, свои
   задачи и свою историю. Чужое отдаёт 404, а не 403 — иначе ответ
   подтверждает, что объект существует.

### ⚠️ Чего вход по логину НЕ даёт

Пароля нет, значит **любой, кто дотянулся до сервера и знает логин коллеги,
войдёт под ним**. Логины предсказуемы — это фамилии. То есть разграничение
здесь разделяет РАБОТУ, а не секреты: чтобы Иванов не путался в документах
Петровой и не стирал её историю.

Это осознанный размен ради того, чтобы сотрудник ничего не вводил каждый день.
Если однажды понадобится настоящая защита от постороннего — это пароли или
доменная аутентификация, и это отдельная работа.

Отсюда же следует: **держать сервер в доверенной сети обязательно.** Гостевой
Wi-Fi, подрядчики, гости с ноутбуками — всё это теперь равносильно доступу к
договорам.

Cookie сессии — `HttpOnly` и `SameSite=Lax`, но **без `Secure`**: внутри сети
идёт обычный HTTP, и с этим флагом cookie просто не отправлялась бы. Значит
сессию можно перехватить, имея доступ к сетевому трафику между компьютером
сотрудника и сервером.

**Решение принято 31.07.2026: запускаем без HTTPS.** Это не забытый пункт и не
недоделка — это принятый риск, и записан он здесь именно поэтому. Что он
означает на практике:

- кто может слушать трафик внутри сети (свой ИТ-специалист, подрядчик с
  доступом к коммутатору, заражённый компьютер в той же сети), тот может
  забрать cookie сессии и работать под чужим логином;
- пароля всё равно нет (см. выше), так что HTTPS закрыл бы перехват трафика,
  но не подбор логина по фамилии. Это две разные дыры, и вторая шире.

**Пересмотреть, если:** сервер станет доступен из-за пределов доверенной сети,
появится Wi-Fi для гостей в том же сегменте, или в приложение попадут данные,
которых нельзя показывать даже своему ИТ-специалисту. Тогда — сертификат,
`ssl_keyfile`/`ssl_certfile` в `scripts/run_server.py` и флаг `Secure` на
cookie.

### Общий компьютер

Логин запоминается на компьютере на год. Если за одним компьютером работают
несколько человек, на форме входа есть ссылка **«не я»** — она стирает
запомненный логин, чтобы следующий не вошёл под чужим по инерции.

**Наружу из компании ничего не публиковать.** Приложение офлайновое, интернет
ему не нужен: выход в сеть ему запрещён кодом, разрешён только localhost.

## Один рабочий процесс, и это не настройка производительности

`scripts/run_server.py` поднимает uvicorn **с одним воркером**. Очередь задач и
их результаты живут в памяти процесса: при двух процессах запрос
`GET /api/tasks/{id}` попадёт в другой процесс и вернёт 404.

Производительности вторым процессом всё равно не добавить — замерено, что
Ollama выполняет запросы к одной модели строго последовательно: два
одновременных дали 24.7 и 48.8 с, три — 24.6, 49.1 и 73.2 с, скорость каждого
не изменилась.

Поэтому сотрудник, отправивший задачу вторым, видит позицию в очереди и оценку
времени — вместо молчания. Оценка берётся из истории задач этой машины, а не из
зашитой константы.

## Что переживает перезапуск, а что нет

| | |
|---|---|
| Готовые результаты | **переживают** — лежат в базе (зашифрованными) |
| Задачи в очереди и в работе | **теряются**, помечаются «прервана перезапуском» |
| Загруженные и готовые файлы | лежат на диске, срок хранения `DATA_RETENTION_DAYS` |

Возобновить прерванную задачу нельзя: работа модели нигде не сохраняется.
Помечать её ошибкой честнее, чем оставить «в очереди» — иначе человек ждёт
ответа, которого не будет.

## Резервное копирование

Копировать нужен один каталог — `data/`:

| | что |
|---|---|
| `data/chroma/` | индекс нормативки |
| `data/app.db` | учётные записи, адресаты, история, результаты задач |
| `data/uploads/`, `data/outputs/` | документы пользователей (зашифрованы) |

**Копия документов бесполезна на другой машине или под другой учётной
записью** — они зашифрованы DPAPI. Это и есть смысл шифрования, но при
восстановлении об этом надо помнить: восстанавливать на ту же машину и под ту
же учётную запись.

## Чек-лист приёмки

- [ ] С двух разных компьютеров открывается, обе сессии работают
- [ ] Без входа приложение недоступно (страницы уводят на форму)
- [ ] Второй пользователь видит позицию в очереди, а не ошибку
- [ ] Одинаково названные файлы от двух людей не перетирают друг друга
- [ ] Сотрудник не видит задачи, файлы и историю коллеги
- [ ] Перезапуск сервера не роняет приложение (задача планировщика поднимает)
- [ ] Готовый результат доступен после перезапуска
- [ ] Скачивание DOCX работает из браузера
- [ ] `/api/health` показывает Ollama и LanguageTool
- [ ] Юр-анализ договора на 17 страниц укладывается в одну часть (в логе
      «1 част(и/ей)») — значит окно модели подобрано по памяти сервера
- [ ] В логе нет обращений к `huggingface.co` — приложение работает офлайн
- [ ] Сервер стоит в доверенной сети, гостевого Wi-Fi в том же сегменте нет —
      без HTTPS это условие обязательное, а не пожелание
- [ ] `git status` в папке проекта чистый после первого запуска — иначе
      автообновление молча отключится (см. `packages/rag/src/.../seed.py`)

## Если что-то не так

**Никто не может войти.** Учётных записей нет — форма входа скажет об этом
прямо. Завести: `python scripts\add_user.py <логин> --admin`.

**Приложение не запускается, в логе «Файлы программы отличаются от
выпущенных».** Сработал контроль целостности кода. Восстановить:
`git reset --hard origin/main`. Если правка намеренная — пересобрать манифест:
`python scripts\build_integrity_manifest.py`.

**«Нормативная база не подключена».** Интерфейс скажет причину: не скачана
модель эмбеддингов (`python scripts\warm_models.py`) или пуст индекс
(`python scripts\index_corpus.py`). Если написано «отвечает ошибкой» — индекс
повреждён, нужна переиндексация с `--reset`.

**«LanguageTool не установлен».** `.\tools\languagetool\setup.ps1`. Без него
проверка орфографии работает, но идёт через модель — минуты вместо секунд.
