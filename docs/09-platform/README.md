## Три вывода, из которых всё следует

**1. Кастомизация лежит в трёх слоях, и порядок между ними иерархический:**
сначала строка в БД (метаданные), потом файл в клиентском пакете, и только в
крайнем случае код. Правило проверки: сколько строк клиентского Python не
проходит через хуки. Цель — ноль.

**2. Противоречие «клиентский код против `integrity.json`» решается
конструкцией, а не дисциплиной.** Развести корень кода и корень данных,
манифест генерировать из `git ls-files` — тогда он физически не может покрыть
клиентский файл. Плюс второй манифест для пакетов с мягким отказом: расхождение
в ядре валит запуск, расхождение в пакете отключает пакет и показывает баннер.

**3. Декларативный слой окупается с четвёртого справочника.** До этого писать
страницы руками дешевле. Это надо честно себе сказать, чтобы не строить движок
ради одного экрана.

**4. Модель нигде не производит числа.** LLM выдаёт правило, спецификацию или
сопоставление — детерминированный движок применяет его ко всем строкам и
показывает превью. Проверить одно правило дёшево, проверить 500
сгенерированных ячеек дороже, чем набить руками. Это же ответ на вопрос, зачем
вообще офлайн-модель на 7B там, где есть Copilot: она нужна не для чисел.

**5. Память вместо модели.** Каждая правка пользователя пишется в SQLite как
«нормализованный ключ → результат». Со второго месяца модель зовётся на единицы
процентов строк. Именно так устроено разнесение выписки в Контур — это таблица
соответствий, а не нейросеть.
