# ADR-0004 · RAG на ChromaDB и multilingual-e5-large

**Дата**: 2026-07-14 · **Статус**: принято

## Контекст

Юридический анализ договора требует **ссылок на конкретные статьи ФЗ, ГК,
СП**. Модель без подсказок галлюцинирует — придумывает несуществующие
номера статей. Решение — RAG: индексируем корпус нормативки, при анализе
подтягиваем 5–6 релевантных чанков в промпт.

Требования:
- Работает офлайн, embedded (без отдельного сервиса).
- Поддерживает русский язык.
- Индекс на 10–100 тыс. чанков (весь ГК + ФЗ + СП + ГОСТ).
- Быстрый top-k поиск (< 500 мс на запрос).

## Решение

**Векторная БД**: [ChromaDB](https://www.trychroma.com/) в embedded-режиме.
Хранит индекс в `data/chroma/` как файлы. Zero-config, one-line запрос.

**Эмбеддер**: `intfloat/multilingual-e5-large` (sentence-transformers,
~1.3 ГБ). Топ по русскому в бенчмарках MTEB на момент выбора.

**Чанкинг**: по 500 слов с перекрытием 50 (простой word-split, без сложной
семантики — для нормативных актов работает достаточно хорошо).

**Идемпотентность**: файлы индексируются по SHA-256 контента, повторный
запуск пропускает уже проиндексированные.

## Альтернативы

1. **Qdrant / Milvus / Weaviate** — правильнее для кластера, но требует
   отдельный сервис. Отвергнуто для MVP.
2. **FAISS напрямую** — быстро, но без метаданных, HNSW настроек, TTL.
3. **Только keyword search (BM25)** — не понимает синонимов и переформулировок.
4. **Промпт-инъекция «пропиши всю нормативку»** — не влезет в контекст.

## Последствия

**Плюсы**:
- `chromadb.PersistentClient(path=...)` — одна строчка настройки.
- Быстрый первичный индекс: 84 KB корпуса → 13 чанков за 15 секунд.
- Поиск даёт релевантные ссылки: `ст. 401 ГК РФ`, `ст. 723 ГК РФ` — реальные
  статьи из проиндексированных файлов.

**Минусы**:
- Эмбед-модель весит 1.3 ГБ — качается при первой индексации.
- Sentence-transformers тянет torch (~200 МБ).
- При большом корпусе (100+ файлов) индексация занимает часы. Для
  MVP-корпуса (8 файлов) — минуты.

## Границы модуля

RAG вынесен в отдельный пакет `packages/rag` (`fire_safety_rag`):
- Не зависит от backend/frontend.
- Собственный `config.py` через env-vars.
- `text_reader` — параметр `build_index`, что позволяет расширить корпус
  сложными форматами (DOCX, PDF) без правки RAG-кода.
