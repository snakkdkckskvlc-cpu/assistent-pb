# ADR-0003 · Ollama как локальный runtime для LLM

**Дата**: 2026-07-14 · **Статус**: принято

## Контекст

Ключевое требование заказчика: **приложение должно работать полностью
офлайн**, без обращения к облачным LLM. Данные (договоры, предписания)
не должны покидать сервер компании.

Нужен локальный runtime, который:
- Работает на CPU (у заказчика Ryzen 5 5600, 128 ГБ RAM, GPU нет).
- Поддерживает русскоязычные модели (Qwen 2.5).
- Имеет HTTP API (backend уже на HTTP).
- Ставится одной командой на Windows и macOS.

## Решение

Используем **Ollama** — обёртку над llama.cpp с HTTP-сервером на
`127.0.0.1:11434`.

Модель по умолчанию:
- **dev/тестировщик**: `qwen2.5:7b-instruct` (~4.7 ГБ), быстро скачивается.
- **боевой сервер**: `qwen2.5:14b-instruct-q4_K_M` (~9 ГБ), лучше качество.

Модель конфигурируется через env `LLM_MODEL`.

## Альтернативы

1. **llama.cpp напрямую** (без Ollama) — меньше зависимостей, но нужно
   писать свою обёртку, управлять моделью, лицензиями. Отвергнуто.
2. **vLLM / TGI (HuggingFace)** — быстрее на GPU, но требуют NVIDIA GPU.
3. **LM Studio** — есть GUI, но нет headless-режима под сервер.
4. **Облачный API (OpenAI, YandexGPT)** — нарушает офлайн-требование.

## Последствия

**Плюсы**:
- Один инсталлятор на Windows (`.exe`), macOS (`.dmg`), Linux.
- HTTP API совместим с OpenAI-форматом → легко мигрировать при необходимости.
- Модели живут в `~/.ollama/models/`, легко обновляются `ollama pull`.

**Минусы**:
- Дополнительный процесс, который надо поддерживать (mitigation: Ollama
  устанавливается как служба Windows и автостартует).
- CPU-only даёт 4–8 токенов/с для 7B и ~2–4 токенов/с для 14B. Юр. анализ
  договора занимает 3–8 минут на 14B.

## Диагностика

`GET /api/health` возвращает статус модели:

```json
{
  "ok": true,
  "ollama": {"ok": true, "model": "qwen2.5:14b-instruct-q4_K_M", "installed": [...]},
  "rag_ready": true
}
```
