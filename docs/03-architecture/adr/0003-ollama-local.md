# ADR-0003 · Ollama как локальный runtime для LLM

**Дата**: 2026-07-14 · **Статус**: принято

## Контекст

Ключевое требование заказчика: **приложение должно работать полностью
офлайн**, без обращения к облачным LLM. Данные (договоры, предписания)
не должны покидать сервер компании.

Нужен локальный runtime, который:
- Работает на CPU (у заказчика Ryzen 5 5600, 128 ГБ RAM, GPU нет).
- Поддерживает русскоязычные модели (Qwen 2.5).
- Имеет HTTP API (backend уже на HTTP).
- Ставится одной командой на Windows и macOS.

## Решение

Используем **Ollama** — обёртку над llama.cpp с HTTP-сервером на
`127.0.0.1:11434`.

Моделей **две**, и это не «dev против боевого», а разделение по задачам —
обе ставятся на любой машине (`bootstrap.ps1` качает обе, вместе ~11 ГБ):

- **`qwen2.5:7b-instruct`** (~4,7 ГБ) — орфография и «вопрос по документу».
  Там десяток коротких запросов на страницу, и решает скорость ЧТЕНИЯ промпта.
- **`GigaChat3.1-10B-A1.8B`** (~6,5 ГБ, MoE, MIT) — юридический анализ
  договоров. Замер на пяти размеченных договорах: F1 **0,752** против 0,505 у
  qwen2.5, при этом на 11% быстрее.

Скорости сама MoE-архитектура не дала: при одинаковом окне генерация 4,9 ток/с
против 5,0 у плотной 7B — паритет. Выигрыш по времени пришёл не от модели, а
от того, что её ответы перестало быть нужно переспрашивать (см. починку
формата в `infrastructure/llm.py`).

Конфигурируется через env: `LLM_MODEL` (общая), `LLM_MODEL_LEGAL`,
`LLM_MODEL_SPELLCHECK`.

**14B пробовали и отказались.** Плотная 14B на CPU даёт ~2–4 токена/с, то есть
юр. анализ уходит за полчаса. Замер по качеству этого не оправдал: 10B MoE
даёт лучший разбор при вдвое большей скорости.

## Альтернативы

1. **llama.cpp напрямую** (без Ollama) — меньше зависимостей, но нужно
   писать свою обёртку, управлять моделью, лицензиями. Отвергнуто.
2. **vLLM / TGI (HuggingFace)** — быстрее на GPU, но требуют NVIDIA GPU.
3. **LM Studio** — есть GUI, но нет headless-режима под сервер.
4. **Облачный API (OpenAI, YandexGPT)** — нарушает офлайн-требование.

## Последствия

**Плюсы**:
- Один инсталлятор на Windows (`.exe`), macOS (`.dmg`), Linux.
- HTTP API совместим с OpenAI-форматом → легко мигрировать при необходимости.
- Модели живут в `~/.ollama/models/`, легко обновляются `ollama pull`.

**Минусы**:
- Дополнительный процесс, который надо поддерживать (mitigation: Ollama
  устанавливается как служба Windows и автостартует).
- CPU-only даёт 4–8 токенов/с для 7B и ~2–4 токенов/с для 14B. Юр. анализ
  договора занимает около 7 минут на нынешней паре моделей (замер: 1983 с на
  пять договоров).
- **Две резидентные модели вместо одной.** При `LLM_KEEP_ALIVE=-1` в памяти
  висят обе — вместе ~11,7 ГБ. На сервере со 128 ГБ это ничто, но на машине с
  12 ГБ они уже не помещаются: по отдельности каждая влезает, вместе нет.
  `/api/health` считает сумму и предупреждает.

## Диагностика

`GET /api/health` возвращает статус модели:

```json
{
  "ok": true,
  "ollama": {
    "ok": true,
    "model": "qwen2.5:7b-instruct",
    "models": ["qwen2.5:7b-instruct", "hf.co/ai-sage/GigaChat3.1-10B-A1.8B-GGUF:Q4_K_M"],
    "installed": [...],
    "warning": null
  },
  "rag_ready": true
}
```
