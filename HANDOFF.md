# Ассистент ПБ — что это и что с ним сделано

Файл для того, кто входит в проект: новый разработчик, новый диалог с
ассистентом, вы сами через месяц. Читается сверху вниз, вставляется в начало
нового чата целиком.

Состояние на 31.07.2026. Всё запушено в `main`.

---

## 1. Что это

**Ассистент ПБ** — локальный офлайн ИИ-ассистент для ООО «ПожСервис» (Липецк,
пожарная безопасность; основной заказчик — ПАО «НЛМК»).
Приватный репозиторий: [snakkdkckskvlc-cpu/assistent-pb](https://github.com/snakkdkckskvlc-cpu/assistent-pb).

Пять функций: проверка орфографии, юридический анализ договора, официальное
письмо на фирменном бланке, пакетная проверка договоров, свободный вопрос по
документу (ответ только из файла, со ссылками на места в нём). Плюс история задач,
кнопки 👍/👎, справочник адресатов.

**Стек:** Python 3.12 **на боевом сервере** (на сборке 3.11, на ноутбуке
разработчика 3.13 — разбор в `CLAUDE.md` §3), FastAPI, Ollama
(`qwen2.5:7b-instruct`), ChromaDB +
`intfloat/multilingual-e5-large`, LanguageTool, SQLite. Десктопная оболочка на
pywebview осталась, но основной режим теперь серверный.

**Железо сервера:** Ryzen 5 5600, 128 ГБ RAM, **без видеокарты**, Windows.

**Состояние:** 670 тестов зелёные, ruff чистый, манифест целостности сходится
(112 файлов), корпус согласован, поиск с фильтром работает.

Проверено запуском, а не только тестами: сервер поднимается, контроль
целостности на старте сходится, `/api/health` отдаёт `ollama.ok`,
`rag_ready`, `languagetool_ready` — все `true`; без входа `/` уводит на форму
(303), `/api/tasks/{id}` отдаёт 401.

## 2. Главное, что поменялось: приложение переехало на сервер

Раньше оно ставилось на каждый компьютер и слушало `127.0.0.1`. Теперь стоит
на **одном сервере**, сотрудники открывают его браузером, вычисления идут на
сервере. Порядок развёртывания и чек-лист приёмки —
[docs/07-ops/install-server.md](docs/07-ops/install-server.md).

Из этого следует всё остальное в этом файле: то, что было безопасно на одном
рабочем месте, на общем сервере перестало быть безопасным.

### Запуск на сервере

```powershell
python scripts\add_user.py ivanov --admin   # без этого войти некому
python scripts\run_server.py                # 0.0.0.0:8000, один воркер
.\tools\service\install_task.ps1            # автозапуск при загрузке
```

Скрипты можно запускать **любым** python — они сами находят venv проекта.

## 3. Безопасность: что сделано и чего это НЕ даёт

Это самая большая часть работы. Каждый пункт снабжён честной границей —
пожалуйста, не выкидывайте эти оговорки при рефакторинге, они дороже кода.

### Шифрование документов на диске

`data/uploads` и `data/outputs` лежат зашифрованными Windows DPAPI
(`infrastructure/dpapi.py`, `secure_files.py`). Ключ в приложении не хранится —
он производный от учётной записи Windows.

Замерено: 0.5 МБ — 0.07 c, 64 МБ (потолок загрузки) — 4.3 c. На фоне минут
работы модели незаметно. Библиотека `cryptography` намеренно не тянется:
установщик проекта хрупкий, а DPAPI снимает вопрос хранения ключа.

**Не даёт:** защиты от кода, запущенного под ЭТОЙ ЖЕ учётной записью Windows.
Против этого работает только автоочистка (ниже). На сервере под `SYSTEM`
ключи доступны любому администратору машины — поэтому в
`install_task.ps1` есть параметр `-UserId` и предупреждение.

**Опасность:** принудительный сброс пароля Windows администратором уничтожает
master-ключи DPAPI, и все `.enc` становятся мусором. `data/` — не архив.

### Автоочистка

`DATA_RETENTION_DAYS` (по умолчанию 7). Проход при старте и раз в 6 часов,
плюс кнопка «Удалить рабочие файлы» на странице истории.

Перезаписи содержимого перед удалением **нет намеренно**: на SSD с
wear-leveling и на журналируемой NTFS это не даёт гарантии, а создаёт ощущение
защиты, которой нет.

### Запрет выхода в интернет

`infrastructure/netguard.py` патчит `socket.connect`, `connect_ex` и
`getaddrinfo`, пропуская только loopback. Обращений к `huggingface.co` стало 0
(было несколько десятков на холодный старт).

**Не даёт:** это не песочница. Патч внутри процесса, и код, который сознательно
его снимет, выйдет в сеть. Настоящая изоляция — правило файрвола, но оно
сломает автообновление (`pip` идёт тем же `python.exe`), поэтому отложено.

**Следствие:** модель эмбеддингов теперь качает установщик явно
(`scripts/warm_models.py`), а не «как-нибудь при первом обращении».

### Границы записи файлов

Приложение создаёт и удаляет файлы только в `data/uploads`, `data/outputs`,
`data/tmp` (`infrastructure/file_access.py`). Это не исправление утечки, а
закрепление инварианта: правка, которая начнёт писать наружу, упадёт на тесте.

### Контроль целостности кода

`integrity.json` — SHA-256 каждого файла рантайма. Приложение (и десктопное, и
серверное) отказывается стартовать при расхождении.

**ВАЖНО ПРИ РАБОТЕ:** после любой правки кода манифест надо пересобрать.

```bash
python scripts/build_integrity_manifest.py
```

Забытый пересбор ловит шаг `--check` в CI — иначе он превратил бы приложение у
сотрудника в кирпич. Переводы строк нормализуются: в репозитории
`core.autocrlf=true`, и без этого манифест с Windows не совпал бы с CI.

**Не даёт:** кто может править код, может убрать и саму проверку. Ловит
«сотрудник поправил», сорванное обновление, побившийся файл. Обход для
разработки — `ASSISTENT_PB_DEV=1`.

### Авторизация — вход ТОЛЬКО по логину

Пароля нет. Сотрудник вводит логин один раз, дальше устройство подставляет его
само (cookie на год), остаётся нажать «Вход». На общем компьютере есть ссылка
«не я».

**Не даёт — и это важно понимать:** любой, кто дотянулся до сервера и знает
логин коллеги (а это фамилия), войдёт под ним. Разграничение разделяет
**работу**, а не секреты. Сервер обязан стоять в доверенной сети; гостевой
Wi-Fi и подрядчики равносильны доступу к договорам.

Что осталось: войти можно только под существующим логином (заводит
администратор), отключение записи закрывает доступ и рвёт сессии.

### Разграничение «только своё»

Сотрудник видит свои документы, задачи и историю. Чужое отдаёт **404, а не
403** — 403 подтверждает существование объекта.

Закрыты три канала, и самый широкий в ТЗ переезда не значился:
`/api/tasks/{id}` отдавал **полный результат** — разбор договора вместе с
текстом документа — любому, кто знает id.

## 4. Что ещё сделано

### Устойчивость к перезапуску

Результаты задач лежат в `task_results` **зашифрованными** (иначе `app.db`
стала бы хранилищем договоров открытым текстом). Прерванные задачи при старте
помечаются ошибкой: возобновить нельзя — работа модели не сохраняется, а
оставить «в очереди» значило бы, что человек ждёт ответа, которого не будет.

### Очередь: позиция и оценка времени

Параллелить не стали, и это замер, а не мнение: Ollama выполняет запросы к
одной модели **строго последовательно**. Два одновременных дали 24.7 и 48.8 с,
три — 24.6, 49.1, 73.2 с; скорость каждого не изменилась. Несколько воркеров
лишь перенесли бы очередь внутрь Ollama, где её не видно.

Раз ожидание неизбежно — показываем позицию и оценку. Оценка берётся из
истории ЭТОЙ машины (медиана последних успешных задач того же вида), а не из
зашитой константы.

### Уникальные имена загрузок

Двое сотрудников с «Договор.docx» перетирали файл друг друга, **и первый
получал в анализ чужой документ**. Теперь на диске `<8 hex>_<имя>`, а
пользователю показывается исходное имя.

### LanguageTool наконец работает

Он не работал никогда, и причин было три: установщик его не ставил; скрипты
установки **не запустились бы** (UTF-8 без BOM → PowerShell 5.1 читает как
cp1251, заглавная «Г» превращается в кавычку и ломает разбор); никто не
поднимал сервер. Всё три закрыто, BOM проставлен пяти скриптам.

Замерено: быстрый режим (`deep=false`) — 3.46 c против 48 c глубокого, находок
одинаково.

### Поиск по нормативке был сломан

Любой векторный запрос **с фильтром** падал с `Error finding id`, а фильтр —
это ровно то, чем пользуется ретривер. То есть анализ договора не работал
вообще. Индекс заменён готовым из git (3281 → 3742 документа, СП 7 редакции
2009 → 2013). Плюс сбой поиска больше не роняет задачу целиком, и
`check_corpus.py --index` теперь проверяет сам поиск, а не только наличие
файлов.

## 5. Что открыто и ждёт решения

1. **Учётная запись сервера.** Под `SYSTEM` шифрование не защищает от
   администратора машины. Выделенная запись лучше, но менять после запуска
   нельзя — старые файлы перестанут читаться.
2. **Автообновление = доверие к GitHub.** Приложение делает `git reset --hard`
   и запускает полученный код. Контроль целостности здесь не спасает:
   обновление приносит и новый манифест. Лечится подписью коммитов — нужен
   ключ, это отдельная работа.
3. **Не проверено то, что требует двух компьютеров:** две сессии одновременно
   и очередь между двумя людьми. Единственный пункт чек-листа приёмки, который
   нельзя закрыть с одной машины.
4. **Дообучение (LoRA) не делалось** — без GPU не потянуть. Кнопки 👍/👎 пишут
   фидбек в SQLite, датасет копится.
5. **Версии в `pyproject.toml` (`0.2.0`) не совпадают с CHANGELOG (`0.9.0`).**
   Разошлись давно; выравнивать или нет — решение не принято.

### Закрыто 31.07.2026

- **Фирменный бланк под контролем целостности.** `templates/` больше не
  исключён, манифест 104 → 106 файлов. Цена записана в
  [docs/05-quality/security.md](docs/05-quality/security.md): свой бланк →
  пересобрать манифест, иначе приложение не стартует.
- **HTTPS — решение принято: не делаем.** Это принятый риск, а не недоделка;
  последствия и условия пересмотра записаны в
  [docs/07-ops/install-server.md](docs/07-ops/install-server.md). Держится на
  одном условии: сервер в доверенной сети.
- **CHANGELOG догнан** — запись 0.9.0 закрывает весь переезд на сервер.

## 6. Как тут принято работать

- **Коммиты** — conventional commits, сообщения на русском, **без трейлера
  `Co-Authored-By`**.
- **Комментарии объясняют ПОЧЕМУ**, а не что. Особенно ценны оговорки «чего
  это не даёт» — не выкидывайте их.
- **Каждый предохранитель проверяется на способность краснеть**: ломаешь его
  временно и убеждаешься, что падают именно нужные тесты. Зелёный тест,
  который не умеет краснеть, ничего не гарантирует.
- **Измерять, а не предполагать.** Все числа в этом файле — замеры на этом
  железе.
- **Тихая деградация хуже отказа.** Урок пропавшего фирменного бланка:
  генератор молча свалился на запасной путь и месяцами выдавал письма без
  реквизитов. Поэтому везде, где что-то может не сработать, оно говорит об
  этом вслух.

### Перед коммитом

```bash
python -m ruff check . && python -m ruff format --check .
python -m pytest -q
python scripts/build_integrity_manifest.py     # обязательно после правок кода
python scripts/check_corpus.py
```

## 7. Технические заметки по среде (сэкономят время)

- **PowerShell-тул иногда залипает** (любая команда → exit code 66). Обход:
  Bash-тул с `powershell -NoProfile -Command "..."` внутри.
- **Bash-тул не выводит кириллицу** (`?????`/мойибейк). Это не порча данных —
  пишите вывод в файл и читайте через Read.
- **cp1251-краши в Python-скриптах**: `UnicodeEncodeError: 'charmap' codec` —
  это эмодзи в `print()`. В проекте принято ASCII: `[OK]`/`[X]`/`[!]`.
- **PowerShell-скрипты с кириллицей обязаны быть в UTF-8 С BOM.** Без BOM
  Windows PowerShell 5.1 читает их как cp1251, и заглавная «Г» (байты `D0 93`)
  превращается в типографскую кавычку, ломая разбор. Так молча не работали
  пять скриптов.
- **bytes-литералы не принимают кириллицу**: `b"текст"` — синтаксическая
  ошибка. Пишите `"текст".encode()`.
- **ChromaDB не даёт сменить embedding-функцию** у созданной коллекции —
  всегда передавайте ту же `SentenceTransformerEmbeddingFunction`.
- **ChromaDB пишет в базу уже на `PersistentClient(path)`**, до всякого чтения.
  Поэтому `prebuilt_chroma` (эталон в git) читается только через временную
  копию: иначе `git status` перестаёт быть чистым, а обновлялка на грязной
  рабочей копии молча отказывается работать. Соединение с копией надо закрыть
  ЯВНО (`client._system.stop()`) — сброса ссылок и `gc.collect()` не хватает,
  Windows не отдаёт файлы, и копия на 37 МБ остаётся навсегда.
- **Тест на синтетической базе ChromaDB может не уметь краснеть.** База,
  созданная тут же текущей версией, при повторном открытии не меняется — на
  ней проверка «эталон не тронут» зеленела бы и на дырявом коде. Такие тесты
  идут на копии настоящего индекса.
- **Не откатывайте правки через `git checkout`**, если они ещё не
  закоммичены — снесёте работу. Делайте копию файла.
- **venv называется `venv`** (не `.venv`). Скрипты теперь сами его находят.
- **Экран/браузер среды — не экран пользователя**: скриншоты показывают среду.
